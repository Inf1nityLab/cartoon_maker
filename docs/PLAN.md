## Откуда этот план

17.11 в песочнице (`sources/_eval/threejs-nanites`, в git не входит) проверили идею целиком:
- лиса, потом свой робот, играют мини-мультфильм по сценарию-данным (`src/story/*.json`);
- камера меняет планы как в кино, перемотка на любую секунду даёт тот же кадр;
- качество картинки владельцу понравилось — его дают свет, тени, TAA, трава, земля и лес (nanite-lib) демо.

Задача плана — перенести найденное в архитектуру проекта **по частям, компонентами**, а не копией демо.
Демо — MIT: взятые файлы лежат в `vendor/<источник>/` с LICENSE, наши правки помечены `// OURS:`, всё учтено в `sources/catalog.json` и `THIRD_PARTY_NOTICES.md`.

## Как работаем

- Одна задача — одна цель, объём ≤ ~дня. Ветка `task/<номер>-<слово>`, коммиты в неё; в `main` вливает техрук после проверки.
- Отчёт исполнителя: шаги, вывод `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm licenses:check` (и `pnpm e2e`, если менялась картинка), кадры, решения, вопросы.
- Картинку проверяем глазами на кадрах с фиксированных камер, не только тестами.
- Песочницу не правим без задачи; из неё читаем и переносим по разбору.
- Harness и замеры GPU — по одному за раз.
- Каждая задача — в своей рабочей копии `/Users/baies/studio-wt/<задача>`; e2e — со своим портом: `E2E_PORT=<порт> pnpm e2e`.
